# 발표용 기술 도표 (텍스트 초안)

> 발표 슬라이드 1장에 들어가도록 폭을 좁게(약 72자) 구성한 텍스트 도표.
> 추후 다이어그램 툴(draw.io/PPT 도형 등)로 다듬는 것을 전제로 한 1차 초안.

## [도표 1] 경영진·상급자용 — 업무 흐름 중심 (AS-IS → TO-BE)

> 의도: 기술 용어 없이 "무엇이 어떻게 좋아지는가"만 전달.
> 핵심 메시지 = 사람 단계 제거 → 직원이 직접·즉시 + 정확도 검증 완료.

```
════════════════════════════════════════════════════════════════
   자료 추출 업무 혁신 : 위탁 수동 처리 → AI 셀프 조회
════════════════════════════════════════════════════════════════

 ▣ AS-IS  현재 — 단계마다 사람이 개입하는 위탁 처리

   사업소 직원  ▶  업무 담당자  ▶  KDN 시스템  ▶  사업소 직원
   (자료 요청)     (요청 승인)     (자료 추출)     (결과 확인)
        └─────────  수일 소요 · 위탁 비용 발생  ─────────┘

   ⚠ 연 13,582건 요청('25년) · 한전KDN 위탁 의존 · 의사결정 지연

                         │
                         │   AI 자동화 전환
                         ▼

 ▣ TO-BE  개선 — 직원이 직접, 즉시 조회

   사업소 직원   ────────▶   AI Agent   ────────▶   사업소 직원
   (자연어 질문)          (질문→조회 자동)       (결과 즉시 확인)

   예) "2024년 제조업 전력사용량이 가장 많은 시도는?"
        → 경기도 / 68,685 GWh   (표 + 그래프 자동 생성)

────────────────────────────────────────────────────────────────
 ■ 기대 효과
    · 자료 추출 시간   수일  →  즉시
    · 위탁(KDN) 비용   절감
    · 직원 데이터 활용 역량   강화
 ■ 검증 결과
    · 정확도 100% 달성  (현장 활용기준 70% 초과)
    · AI 모델 3종 비교 검증 완료 → 최적 모델 선정
════════════════════════════════════════════════════════════════
```

## [도표 2] 개발자·엔지니어용 — 아키텍처 / 기술 연계 중심

> 의도: 2개 평면으로 분리. (A) 데이터 구축(배치) + (B) 질의 처리(런타임).
> 시맨틱 레이어를 시각적으로 강조 — 정확도 +45.5%p의 실제 기여 요소.

```
════════════════════════════════════════════════════════════════
   Text2SQL 시스템 아키텍처
════════════════════════════════════════════════════════════════

【 A. 데이터 구축  (배치 · 사전 수행) 】

  한전 OPEN API  ─▶  수집·적재 스크립트  ─▶   PostgreSQL
  (bigdata)          collect → build_db       12개 테이블
                     → migrate_to_pg          (계약·산업·청구·복지·
                                               EV·신재생·코드 등)
                                          ※ 운영 목표 DB: Oracle Exadata
────────────────────────────────────────────────────────────────

【 B. 질의 처리  (실시간 런타임) 】

  자연어 질문  (Streamlit UI)
       │
       ▼
  ① normalizer        지역·업종명 → common_code 서브쿼리 힌트
       │
       ▼
  ② semantic_builder  스키마 컨텍스트 조합 (RAG 방식)
       │
       │   ★ 시맨틱 레이어 3종  ◀── 정확도 +45.5%p 의 핵심
       │      · 메타데이터 레이어 : DDL · 컬럼 예시값
       │      · 의미 규칙 레이어   : 단위 · 집계 규칙 · 금지 패턴
       │      · 조인 관계 레이어   : 복합키 · 테이블 JOIN 규칙
       ▼
  ③ generator         OpenRouter / gpt-oss-120b (temp=0)  →  SQL
       │
       ▼
  ④ safety            SELECT·WITH만 허용 · 금지키워드 · 테이블 검증
       │
       ▼
  ⑤ executor          PostgreSQL 읽기전용 · 5초 타임아웃 · LIMIT 100
       │
       ▼
  ⑥ 결과 반환         행·컬럼 구조화 → 표 · CSV 다운로드  (Streamlit)

────────────────────────────────────────────────────────────────
 ■ 핵심 기술  LLM(gpt-oss-120b) · RAG(시맨틱 레이어) · PostgreSQL
 ■ 보안 방어  ④ 안전성 검사 + ⑤ 읽기전용 실행 = 이중 방어
              (INSERT/UPDATE/DELETE 등 쓰기 구문 원천 차단)
════════════════════════════════════════════════════════════════
```

### 표기 기준 (확정)

- **DB**: 런타임 DB는 **PostgreSQL**(`pipeline/db.py`, `executor.py` = psycopg2)로 통일.
  운영 도입 목표는 Oracle Exadata(JOB.md).
- **테이블 수**: 실제 PostgreSQL 적재 기준 **12개**로 통일. (API 핵심 테이블만 적재)
- **파이프라인 단계**: 6단계
  (normalizer → semantic_builder → generator → safety → executor → 결과 반환).
